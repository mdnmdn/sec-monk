# Contracts

The interfaces of the Rust prototype as JSON Schema (draft 2020-12). Explained in
[`../_docs/tech/contracts.md`](../_docs/tech/contracts.md) and [`../_docs/tech/api-contract.md`](../_docs/tech/api-contract.md).

```
schemas/   node/ (mirror-node requests)  wire/ (secmonk-wire/1 envelope)  module/ (manifest)  inventory/  source/ (mirror rows)
           engine/ (classify, match, versions, reports, procmon)  probe/ (docker, discover)
           process/ (secmonk-process-snapshot/1)  api/ (one schema per /api payload)  catalog/
catalog/   module-methods.json (every module method once)   api-routes.json (the 22 /api routes)
examples/  wire/ module/ inventory/ process/ api/   + index.json (example -> schema [+ JSON pointer])
```

- Every schema has `$id` = `https://contracts.secmonk.invalid/<path under schemas/>`; references are relative to it
  (`.invalid` never resolves: validators must load the files, never fetch).
- `examples/index.json` maps each example to the schema it must satisfy; `pointer` selects a part (for example the
  `params` of a `req` frame against the method's params schema). Each example is listed at least once.
- Provenance: `examples/api/*` come from `_design/mock/data.js` (generated by `scripts/design_mock.py` from the test
  fixtures), trimmed; `examples/inventory/fs-npm-v3.json` and the classify frames are real outputs of today's code on
  `tests/fixtures/lang/javascript/npm-v3` and synthetic components, paths anonymized; the rest is synthetic and says so
  in `index.json` (`note`).

## Check

A check passes when (1) every file under `schemas/` passes the draft 2020-12 meta-schema and its `$id` matches its
path, (2) every entry of `examples/index.json` validates (with all schemas loaded into one registry), (3) every
schema path named in `catalog/*.json` resolves, (4) no example is left out of the index. Run it with jsonschema, for
example `uv run --with jsonschema python -I <script>` from a directory outside the repo; the script becomes part of the
Python modules package tests (wave W2.2). Last run: 2026-11-11 (`cd rust/python && uv run python scripts/check.py`: 13 contract tests and the golden outputs pass), 53 schemas, 55 example files, 70 index entries (checks), 0 failures.

## Changing a contract

Additive changes (a new optional field, a new method) keep the version. Anything else is a new version string
(`secmonk-inventory/2`) or a new method name, plus an example, plus the golden outputs that depend on it
([component lifecycle](../_docs/tech/component-lifecycle.md)).
