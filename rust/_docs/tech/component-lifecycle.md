# Standard process: Python first, Rust later

Every new component goes through the same six stages, in this order, with the same artefacts. Python is the fast lane;
the contract and the golden outputs are what make a later Rust port mechanical (proposal §9.4).

```
1 contract  ->  2 Python module  ->  3 conformance + golden  ->  4 manifest + install  ->  5 done
                                                                                          |
                                         6 later: Rust impl -> differential test -> select Rust in config -> retire Python
```

## 1. Define and freeze the contract

- [ ] Pick the **kind** (`probe`, `source`, `engine`, `tool`) and the method names (`<area>.<verb>`), checked against
      [`catalog/module-methods.json`](../../contracts/catalog/module-methods.json) for an existing method to reuse.
- [ ] Write the params and result schemas under `rust/contracts/schemas/<area>/` (draft 2020-12, `$id` from the path,
      `additionalProperties: false` on params, bounded strings and arrays). Reuse `inventory/`, `source/rows`,
      `api/*` payloads instead of new shapes.
- [ ] Decide `unary` or `stream` (anything that can exceed ~1 MB or 1 000 items streams) and the `end` result.
- [ ] Add the method to the catalog with `effect` (`read`, `read-target`, `network`, `stateful`, `staging`).
- [ ] Add at least one example per params/result under `rust/contracts/examples/`, listed in `examples/index.json`;
      the contract check passes ([contracts README](../../contracts/README.md)).
- [ ] Write down the error codes it may return (from the [wire list](contracts.md#a-module-protocol-secmonk-wire1)).
- [ ] **Frozen** means: merged, examples valid, and from now on only additive changes; a breaking change is a new
      method name.

## 2. Implement it as a Python protocol module

Layout of `rust/python/` (uv project `secmonk-modules`, depends on the repo's `secmonk` package via
`[tool.uv.sources] secmonk = { path = "../..", editable = true }`; built by W2.2, 2026-11-11):

```
rust/python/
  pyproject.toml, uv.lock            pinned dependencies (lock hash = manifest integrity.lock_sha256); dev: pytest, ruff, jsonschema
  modules/<name>.toml                manifests (secmonk-module/1), generated by scripts/gen_manifests.py
  src/secmonk_modules/
    __main__.py                      `python -I -m secmonk_modules serve <module> --stdio` (or `serve --stdio --module <module>`)
    wire.py                          framing, envelope, hello, dispatch, cancel, caps, stdio guard, MethodTable
    errors.py, common.py             wire error codes, JSON <-> secmonk.models, option parsing
    db.py                            read-only connections from the hello grant (engine modules only)
    client.py                        a minimal host-side client (tests, golden recording, scripts)
    probe/ sources/ engine/ procmon.py   one package per module; one file per method group, thin adapters over secmonk
  scripts/                           golden.py (cases, record/compare), check.py (contracts + manifests + golden), gen_manifests.py
  tests/                             protocol, conformance, golden, safety, sources, engine (pytest, offline)
rust/golden/                         <method>/<case>.params.json + .out.json, normalize.json + normalize.py, README.md
```

- [ ] The adapter is **thin**: parse params, call the domain function (existing `secmonk` code or a new pure
      function), shape the result. New domain logic goes in its own module with plain functions that take data and
      return data, so a Rust port has one function to mirror.
- [ ] Entry point is the shared server (`serve <module> --stdio`); a method is registered on the module's `MethodTable`
      (`@TABLE.unary(name, params)` / `@TABLE.stream(name, params)`; a stream handler is a generator whose `return` value is
      the `end` result). `params` is a light type spec (unknown keys and wrong types are `invalid-params`); the JSON Schemas
      are enforced by the conformance tests, not at run time. No module writes its own framing.
- [ ] Logging: `logging` to **stderr** only, one line per record (`LEVEL logger: message`); request-scoped lines may go
      as `notify log`. Never `print`; the server points fd 1 to stderr anyway.
- [ ] Dependencies: add them to `rust/python/pyproject.toml`, `uv lock`; a new dependency needs a reason in the commit
      message (AGENTS.md). No network at import time.
- [ ] **Untrusted targets** (probe modules): read scanned trees only through `collectors/base.read_within` /
      `resolve_within`, with size caps; never extract archives blindly; commands run on a target are fixed, read-only
      and listed in the module's doc; no "execute this" parameter.
- [ ] **Redaction**: anything that can carry a secret (command lines, URLs, labels, env) goes through
      `redact_command`, `strip_url_secrets`, `redact_labels`, `scrub_text` before it leaves the module.
- [ ] **No vulnerability APIs** outside `source.*`; probe and engine modules never fetch advisories.
- [ ] **No writes** outside the module's own `modules/<name>/` directory and the job scratch dir; engine modules use
      `secmonk_modules.db` (read-only) and never `secmonk.db.connect`.
- [ ] Cancellation is cooperative: `ctx.check()` / `ctx.progress()` between items or chunks raise `Cancelled` (a
      `BaseException`, so library `except Exception` cannot swallow it). A call into unchanged code that cannot check (a
      collector walking a tree) finishes or is killed by the host after `cancel_grace_s`.
- [ ] Options that make unchanged code write a file the caller names (`snapshot_out`) are refused by the module; options
      that choose what runs (`ssh_bin`, `kubectl`, …) are the host's policy (api-contract.md), not the module's.

## 3. Conformance tests and golden outputs

| Test | What it checks | Where |
|---|---|---|
| Schema | every params / item / end / result of every golden case and of the live-only methods validates against the catalog's schemas; every frame against the envelope; the contract check itself (schemas, examples, catalog, manifests) | `tests/test_conformance.py`, `tests/test_contracts.py` |
| Protocol | hello first; unknown method → `unknown-method`; bad params → `invalid-params`; cancel → `cancelled` within the grace; stdout pollution does not corrupt frames; exits on stdin EOF | `tests/test_wire.py` (shared, once) |
| Golden | the method's output on shared fixtures equals the stored golden file after normalization | `rust/golden/<method>/<case>.params.json` + `.out.json`; cases in `scripts/golden.py`, test in `tests/test_golden.py` |
| Safety | fixture trees with escaping symlinks, oversize files (a sparse 300 MB file), archives with `../` entries; no secret in outputs or errors; fixtures never modified | per module (`tests/test_probe.py`, `tests/test_engine.py`) |
| Adapter | for a source: the streamed row operations replayed on an empty mirror equal the staging database; replay/ack/export | `tests/test_sources.py` |
| Environment | `SECMONK_DB` (`python-home/forbidden.db`) never appears; nothing written outside the allowed dirs; a read-only connection cannot write or attach | `tests/test_probe.py`, `tests/test_engine.py` |

- [ ] Fixtures: reuse `tests/fixtures/` of the repo (read only, by path); build trees at test time rather than
      committing binaries; a new fixture gets a README with provenance (real-trimmed, synthetic), no real hostnames,
      user names, serials, tokens or `/Users/<real-name>` paths.
- [ ] Normalization for golden files: sort list items by a stable key (components by purl/category/name/version, findings
      by `(component, vuln_id)`), replace the fixture, repo and data roots with `<fixtures>`, `<repo>`, `<data_dir>`, replace
      timestamps, durations and pids. The rules are data (`rust/golden/normalize.json`) with a Python implementation next to
      them (`normalize.py`); the Rust runner implements the same rules.
- [ ] Goldens are regenerated only by an explicit command (`uv run python scripts/golden.py --update`) and reviewed as a
      diff; `scripts/golden.py` alone compares. A DB-backed case runs on the standard test store built by `tests/dbfactory.py`
      (the host's schema-v3 migration SQL when `rust/crates/secmonk-store/migrations/` exists, else the v2 DDL of `secmonk.db`
      split into a state and a mirror file; v3 is a superset), filled by the unchanged Python (sources on fixtures,
      `save_inventory`, `match_asset`). Streams are recorded merged (see `rust/golden/normalize.json`).

## 4. Manifest, install, launch

- [ ] Add or extend `rust/python/modules/<name>.toml` (`provides`, `capabilities`, `platforms`, `limits`; it is generated by
      `scripts/gen_manifests.py` from the contract example plus what the module announces: the registry of `secmonk` is the
      truth for `collectors` / `sources`, `tests/test_contracts.py` fails when manifest and `hello` differ); a new
      capability must be justified in the PR; `db-read` only for engine modules.
- [ ] Enable it in `sec-monk.toml` `[modules] enabled` (dev); for a release, pin `lock_sha256` / `tree_sha256`
      (`uv run python scripts/pins.py` prints the `[modules.pins]` block; the tree hash covers `pyproject.toml` and
      `src/`, [configuration § Module integrity](configuration.md#module-integrity)).
- [ ] How the host gets it running (no step is manual): read the manifest → check `enabled` and pins → ensure uv
      (`tools/uv-<v>`, sha256) → `uv python install` → hash `uv.lock` + sources (pinned: compare with the pins,
      `secmonk_runtime::verify_module_tree`) → `uv sync --frozen` into `venvs/<env>` (skipped if the install
      stamp matches) → verify again and spawn `venvs/<env>/bin/python -I -m secmonk_modules serve --stdio --module <name>` (the manifest's `python.entry`) with the
      [module environment](configuration.md#module-process-environment) scoped by its capabilities (`command_for`) → `hello` exchange → `provides` checked
      against the manifest → ready. The host runs this as the `ModuleEnv` and `Modules` phases of `Host::start`
      ([architecture §3](architecture.md#3-composition-secmonk-host-and-the-desktop-app)); `lifecycle.start = "eager"`
      modules start then, the others on their first call, and `idle_timeout_s` / `max_restarts` decide when they stop
      and restart ([module lifecycle](architecture.md#4-transports)).

## 5. Definition of done

- [ ] Contract frozen (stage 1), check green.
- [ ] Module implemented with the stage 2 rules; `uv run pytest -q` and `uv run ruff check` in `rust/python` green, offline;
      `uv run python scripts/check.py` (contracts, manifests, golden) green. The lock must also resolve with the pinned uv.
- [ ] Golden files for every fixture case, reviewed.
- [ ] Reachable end to end: host → module → API route or job → the UI shows it (or a CLI/test harness for
      non-UI methods).
- [ ] Docs: the method in [contracts](contracts.md) or [api-contract](api-contract.md), a `tech/` page for a new
      collector or source, plan items for what needs a real machine.
- [ ] No edit in `src/` (if the `secmonk` package needs a change, it is a separate change to the Python version, made
      by its owners).

## 6. Later: the Rust port

- [ ] Implement the domain trait (`Collector`, `Source`, `Classifier`, `Matcher`, …) in a new crate
      (`secmonk-collect-<name>`), depending only on what the [dependency rules](architecture.md#dependency-rules)
      allow; port the safety helpers it needs from `secmonk-safeio`.
- [ ] **Differential test**: run the Python module and the Rust implementation on every golden case (and on extra
      generated cases, for versions: the univers-backed Python oracle); normalized JSON must be equal. Differences
      are bugs in one of the two until explained in the test file.
- [ ] Rust manifest (`runtime = "rust"`, `rust.crate`, `rust.factory`); the registry picks it over the Python one when
      both provide the same name and the config enables it. The choice between the two is a per-component
      selection key in `sec-monk.toml`; for sources it is `[sources.implementation]` (`kev = "rust"` or `"python"`).
      Worked example: `kev`, see [source-kev](source-kev.md) and [ADR-0011](../decisions/0011-native-sources.md); for
      a source, follow [Porting a source to a native importer](#porting-a-source-to-a-native-importer).
- [ ] Keep the Python module as the test reference for one release, then retire it, or keep it as the fallback for a
      platform without a Rust build. Never two production bindings longer than that.

## Porting a source to a native importer

Stage 6 for a vulnerability source ([rust ADR-0011](../decisions/0011-native-sources.md),
[ADR-0012](../decisions/0012-native-importer-row-reads-and-registry.md)). Worked examples: kev (snapshot with deletes),
epss (upserts only), euvd (records with children replaced against stored rows), msrc (rows of one of several input
documents, two passes), debian-tracker (a whole table compared page by page, a streamed download). Every item below is a new file except
the two marked **append**, so importers are ported in parallel without editing the same lines.

| # | What | Where |
|---|---|---|
| 1 | The importer: `pub const NAME`, `pub const IMPORTER: crate::Importer { name: NAME, default_rust: false, new: \|view\| Arc::new(XSource::new(view)) }`, a struct implementing `Source` (`native() = true`, `ack` a no-op, `export` = `native::export_refused`), `run` = `native::limit` + load + `Outcome` + `native::first_seq` + `native::stream`. Unit tests of its parsers in the same file. | new `rust/crates/secmonk-sources/src/<module>.rs` (module = the source name with `-` as `_`) |
| 2 | Registration: one line `<module>,` in the `importers!` list, alphabetical | **append** in `rust/crates/secmonk-sources/src/lib.rs` |
| 3 | Importer tests over `common::MemView` (in-memory view that applies batches and pages by rowid like the store) and `common::serve_logged` / `serve_headers` (local HTTP server; `serve_headers` adds headers such as a redirect's `Location`): rows of the fixture, a second run, changes, limit, every error message, caps, the API request lines | new `rust/crates/secmonk-sources/tests/<module>.rs` (`mod common;`) |
| 4 | Differential test against `py-sources` on the `Diff` harness: `py`, `rs`, `switch` mirrors; first sync, no-op, update, limit, guard / errors with Python's wording (`check_entries` + `assert_mirrors_equal`), the switch to the native importer (log `<source>: native importer: applied state of generation`) and back (failed run: `not applied`; ok run: repair, `assert_mirror_equals_staging`); a mirror with another history compares only its own rows (`assert_source_rows_equal`); then `check_row_contract` with deletes among the cases. Run with `SECMONK_REQUIRE_VENV=1`. | new `rust/crates/secmonk-engine/tests/native_<module>.rs` (`mod common; use common::*;`) |
| 5 | Default: `default_rust: true` in the importer's own `IMPORTER` only once item 4 is green | the file of item 1 |
| 6 | Doc: selection, one sync (step table), caps with their messages and the worst-case memory, diff strategy (which `MirrorView` reads, how deletes are keyed), differences from Python (table), tests (table), fixtures | new `rust/_docs/tech/source-<name>.md` (copy the layout of [source-euvd](source-euvd.md)) |
| 7 | INDEX row, plan and README items | report them to the coordinator (not edited by porting agents) |

Rules for the importer:

- **Shared code first** (the API below): an importer does not keep its own copy of a download, a decoder, a guard or a
  Python rule that a shared module has.
- **Read**: only through `MirrorView` (`count_rows`, `row_keys` for small keyed tables, `rows_by_id` per chunk of at
  most 500 records, `rows_page` to compare a whole table); never a database handle.
- **Write**: the same mirror rows as `py-sources` leaves, as row operations: helpers in `secmonk_sources::rows`
  (`raw_record`, `vulnerability`, `affected`, `alias_set`, `replace_aliases`, `replace_affected`); Python semantics in
  `secmonk_sources::py`. Shared modules (`native`, `rows`, `py`, `feed`, `decode`, `batch`) are not changed during a
  parallel port: a rule only one source needs stays in its file; report a needed shared change instead.
- **Check before writing**: whatever makes the Python source fail inside its transaction fails the native run before
  the first operation (status `error`, only the `source_sync` row).
- **Untrusted input**: caps on download, decompressed and file size, lines or records, bytes per record, and the memory
  this bounds, stated in the doc; `--path` through `feed::read_bytes` / `open_regular` (a regular file only); URLs and
  messages through `feed::scrub` / `strip_url_secrets`; Python's exception wording (`py::`, `feed::os_error`) where the
  differential test compares messages, differences listed otherwise.
- **Wording**: plain technical text in messages, logs, docs and comments: `<source>: native importer: <operation>`;
  no figurative phrases.

Shared API of `secmonk-sources` (`rust/crates/secmonk-sources/src/`):

| Module | What an importer uses |
|---|---|
| `native` (crate-private) | `limit`, `check_name`, `export_refused`, `first_seq`; `Outcome { status, records, total, cursor, message, ops }` (`records` = the end entry's records, `total` = `source_sync.records` when it differs, as msrc's `SyncResult.total`), `Outcome::error`, `iter_ops`, `stream`; `snapshot_guard(old, new, full)` (the text without prefix: the importer adds `<source>: `); `internal(source, msg)` (`<source>: native importer: <msg>`, an internal `WireError`); `Progress::new(ctx).line(..)` (job log lines, scrubbed) |
| `feed` | `Get { url, max_bytes, allow_http, timeout, accept, too_large, same_origin_redirects }`; `get(&Get) -> (bytes, Validators { etag, last_modified })`; `get_streamed(&Get, parse)` (the body parsed on the blocking pool while it arrives, through a `BodyReader` fed by a bounded channel of 16 chunks; cap, scrubbed errors and an early parser stop handled there); `download`, `download_json`; `origin`, `same_origin`; `read_bytes`, `read_json`, `open_regular` (`FileError`); `exists_like_python` (`Path.exists()`, Windows codes included), `rglob` (`Path.rglob` with entry and file caps, `TooMany`); `os_error`, `py_exception`, `py_path`, `py_repr`; `json_error(&e, own_prefixes)`; `scrub`, `parse` |
| `decode` | `open_decoded(reader, cap, &Messages { source, too_large, too_large_gzip }) -> Decoded`: compression from the magic bytes (gzip, plain; bzip2 and xz refused), the cap, a leading BOM skipped; `Decoded` is a `Read` with `take_error` (the first I/O error's text, a cap or a download failure, instead of the parser's), `message(&e)`, `sha256()` (of the decompressed bytes, BOM included); `sniff`, `hex`, `msg_error` / `io_message` |
| `py` | `strip`, `split_ws`, `is_space`, `float_str`, `truthy`, `type_name`, `float_repr`, `repr`, `repr_str` / `repr_str_into` (with `is_printable`), `str_of`, `iter_items` (a lazy `for x in (v or [])`), `no_attr(type, attr)`, `utf8_error` / `decode_utf8` |
| `rows` | `raw_record`, `vulnerability`, `affected`, `alias_set`, `replace_aliases`, `replace_affected` (`DeleteKey::Row` / `Record`), `group_by`, `norm_vendor_product`, `severity_from_score`, `normalize_severity` |
| `batch` | `Limits`, `Cutter`, `cut` (used through `native::stream`) |

Kept in an importer on purpose: epss's gzip reading (gzip chosen by file name, its own messages), its `finite_float`
(`float_str` without infinities), msrc's two-pass state, debian-tracker's compact rows.

## Worked example: the `fs` collector

| Stage | For `fs` |
|---|---|
| 1 Contract | Methods `collector.expand_targets` and `collector.collect` (already in the catalog); params `{collector: "fs", target: "<dir>", options: ["binaries=false", "max_files=1000"]}` (`collect-params`); stream items `asset` / `components` / `warning`, `end` `{partial, partial_reason, components, warnings}`. Options of `fs`: `binaries` (bool), `max_files` (int), `asset_id`. Example: [`examples/inventory/fs-npm-v3.json`](../../contracts/examples/inventory/fs-npm-v3.json) (real output on a fixture). |
| 2 Module | `secmonk_modules/probe/collect.py`: look up `REGISTRY["fs"]`, `ops.parse_opts(options)`, call `collect(target, **opts)` **without** `classify`, then emit `asset`, chunks of 1 000 components, warnings, `end`. The `fs` code itself (`collectors/fs.py`, `collectors/lang/walk.py`) is untouched and already uses `resolve_within`, size caps, no symlink following, `strip_url_secrets` for git remotes. |
| 3 Tests | Golden cases `collector.collect/fs-*` from `tests/fixtures/lang/*` (npm v1/v3, pnpm v9, yarn v1, poetry, requirements, Java, .NET, PHP) and one with binaries (`lang/go`, `binaries=true`); `tests/test_probe.py` builds trees at test time: a symlink to `/etc/passwd` or to a file outside the tree, a symlink loop and a sparse 300 MB lockfile yield no component from them and the module stays up; a `.git/config` remote with a password never reaches the output; the asset id `dir:<fixtures>/lang/go` is normalized. |
| 4 Manifest | `py-probe` already provides `fs`; nothing to install beyond the shared env. The host's `/api/collectors` lists it from `hello.provides.collectors`. |
| 5 Done | `POST /api/jobs {kind: scan, collector: fs, target: …}` shows the components and findings in the UI; job log carries the module's progress lines. |
| 6 Port | Crate `secmonk-collect-fs` + `secmonk-lang` (the 7 ecosystem parsers) + `secmonk-safeio`; differential test on the same golden cases; manifest `rs-collect-fs` ([example](../../contracts/examples/module/rs-collect-fs.json)) enabled instead of `fs` from `py-probe`; Python `fs` stays the reference for one release. |
