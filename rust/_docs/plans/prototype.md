# Plan — Rust prototype

Owner of this file: the coordinator. Agents report; they do not edit this file.

Goal: a working single-process Tauri app in `rust/` with the current interface (`src/secmonk/web/static`, served in
place) and the current probes (collectors) and sources, running as Python modules launched through an embedded,
pinned uv. Architecture ready to split probe / engine / ui across processes and hosts later
(see `_docs/inbox/2026-11-08-port-to-compiled-stack.md`). The Python version in `src/` stays as is and runs in parallel.

Assumptions (cheap to reverse, confirm or correct):

- A1 Folder `rust/`; docs in `rust/_docs/`; this plan in `rust/_docs/plans/`.
- A2 (user, 2026-11-11) Start with a pinned uv version downloaded at app start into `<data_dir>/tools/`,
  checksum-verified. **Everything uv writes stays in `data_dir`**: binary, cache, Python interpreters, venvs.
  Behind a `PythonRuntime` trait; uv-as-crates stays a later option.
- A2d (user, 2026-11-11, refined) macOS and Windows ship all components (probe, engine, ui), with
  per-platform features enabled/disabled; Linux ships engine and probe, and the ui if possible.
- A2e (coordinator proposal, user said go) Python engine modules open the SQLite DB read-only for heavy queries;
  all writes go through the Rust host over the protocol (one writer). ADR + flagged for user review.
- A2b (user, 2026-11-11) Rust holds only the central parts this phase: Tauri shell, config, store (schema v3),
  module host (protocol, registry, uv), API router, jobs/orchestration. Probes, sources, classify/match/scoring,
  versions stay Python. Full Rust migration in later phases, after the prototype works and is well tested.
- A2c (user, 2026-11-11) Document one standard, repeatable process for building a component in Python that may
  later be ported to Rust (contract → Python module → conformance/golden tests → manifest → later port + differential).
- A3 Python modules live in `rust/python/` and import the existing `secmonk` package (path dependency); `src/` is not edited.
- A4 New schema owned by Rust (SQLite first, `Store` trait ready for PostgreSQL/MySQL), stored under `data_dir` from `sec-monk.toml`; dev `data_dir = "_data"` (gitignored), so both versions can run side by side.
- A5 Version-range evaluation, like classify/match/scoring, stays a Python module this phase (see A2b).

## Open choices (coordinator defaults, cheap to reverse; for user review)

- Q1 ADR-0006 accepted by the user (2026-11-11): Python engine modules read the DB read-only; all writes go through the host.
- Q2 ADR-0010 kept as proposed: py-sources run the unchanged sources on a v2 staging file and stream row ops; the
  host writes the mirror (keeps the user-approved one-writer rule). Cost: a second mirror copy on disk; direct write
  is the documented fallback.
- Q3 (user, 2026-11-11) `./sec-monk.toml` is looked up in every build, after `--config` and `SECMONK_CONFIG`; the
  single-open ownership/permission checks stay. Later: a well-known config for general settings (backlog).
- Q4 WKWebView data under `~/Library` on macOS: known exception, plan item.
- Q5 No `secmonk.rpc` in `src/` now.
- Q6 py-procmon reads the host and queries the DB until the process monitor is split.
